# 运营机器人本地接入与验收

配套：[指令规划](运营机器人指令接口规划.md) · [群回复文案](运营机器人群回复文案规范.md) · [订单兼容层](../integrations/order_backend/README.md)。

本地指令接口默认关闭。代码可用临时 SQLite、模拟订单传输和模拟 AI 表格验证。真实运营机器人接收程序、运行主机、钉钉组织和试点群仍需逐一核对；本地测试结果不能替代真实 @、ERP 结果或在线表格回读。

## 工作台和接收程序

- 同机启用时，由部署环境为工作台与原接收程序注入同一个独立随机凭证。工作台读取 INVENTORY_OPS_TOKEN（至少 32 位 ASCII）、INVENTORY_OPS_ORG_ID、INVENTORY_OPS_ROBOT_ID；用 INVENTORY_OPS_PORT 选定可用的本机端口。接口只绑定 127.0.0.1，凭证只走 Authorization Bearer，不能用工作台或数据查询令牌替代。
- 本机需要重启后保留接入时，可由部署程序在现用数据目录写入 ops-command-pilot.json（org_id、robot_id、port），以及以当前 Windows 用户 DPAPI 保护的 ops-command-key.dat。文件不进入源码或发行包。接收端在启动时解密同一专用凭证，不传给通用模型或工作台浏览器。
- 在「连接与通知设置 → 运营机器人指令」选择「绑定钉钉群」，填群名并点「识别群信息」。组织、机器人和群 ID 自动填入，重名时先选择；确认群功能后才保存。识别和绑定不修改现有接收程序的群范围。成员逐个填写钉钉成员 ID、指令 ID、店铺 ID；ERP 成本、维护表价格、订单操作人及表格链接分别授权。未绑定群、未授权成员默认拒绝。取消功能立即影响帮助和后续调用；已排队任务照常执行，原成员仍可在启用任务查询的前提下回读。
- 已绑定群可分别编辑功能和成员权限。下载权限模板，按填写说明输入钉钉成员 ID、指令、店铺和附加权限，再选择同一个群导入。先预览新增和变更，确认后合并；未列出的成员保持原权限，表格错误或预览后配置有变更时不保存。
- 原接收程序负责核实真实 @、组织、群、成员、机器人和稳定消息 ID。验证后构造 ops_receiver.VerifiedMention，交给 Receiver.receive。适配器以 LocalCommandClient 调用本机 HTTP；sender 复用原群回复能力，只能在收到可核对回执后返回 sent。没有明确回执时返回 unknown。按原程序的调度定期调用 Receiver.tick，并保留同一回复账本。该模块不会创建另一个 Stream 连接。
- 接收程序从 GET /api/commands/v1/capabilities 查接口版本，POST /api/commands/v1/requests 提交，按原回执 GET /api/commands/v1/requests/{request_id} 查询。任务查询及投递使用 X-Actor-Org-Id、X-Actor-Group-Id、X-Actor-User-Id。POST /api/commands/v1/requests/{request_id}/delivery 用 phase=initial/final 和 state=claim/sent/failed/unknown 记录投递。claim 成功才能发送；断电或超时不自动重发。
- 群内可用「查库存 56281 仓库 库号 店铺 店名」、「添加监控 56281 阈值 5 仓库 库号」、「查订单状态 完整单号 店铺 店名」及「前台库存监控 店名 SPU 完整编号 SKU 完整编号」。店铺名称仅作为查找条件，实际授权使用稳定 ID。

## 数据来源

工作区可选文件 ops-command-sources.json 属于本机部署配置，不能带入 Git。省略来源保持原功能；新增外部来源必须在试点数据中核实。

| 键 | 配置内容 |
| --- | --- |
| inventory_ai | 设为 true 时复用工作台已配置的 AI，只发送本次库存关键词，固定脚本无可靠结果时才调用；仅复查目录可验证的词。 |
| inventory_aliases | 已核对的整词别名到规范型号的映射；没有别名时走原词。 |
| maintenance_prices | 每项填写 path、sheet、shop_id；按核实表头设置 host_price_column（整机到手价）及 part_price_columns（配件位置到明确单价列的映射）。未指定价列时提示价格列待核实，不猜公式或价格。 |
| order_status_bridge | 设为 true 并部署本版订单兼容文件后，调用 Python 3.14 后端。需按 [tiny_tools PR #5](https://gitea.cq360.top/CoreStudio/tiny_tools/pulls/5) 的已合并版本核对依赖和真实返回字段。当前匹配工程的旧锁定提交没有该接口。本地已对照合并提交 2f8f84f 的接口契约，尚未切换生产运行环境。 |
| report_tables | shipping_orders、shipping_shortages、front_stock 各自绑定已核实的钉钉批次表；见下文。 |
| front_report_writer | 复用前台监控在线明细已回读的行，登记到独立批次表。使用同一 profile，且明确限定 shop_ids；未配置时现有明细同步保持原流程。 |

发货和前台批次表的读取配置包含 base_id、table_id、profile、shop_ids，以及 fields 中 scope、batch、checked_at、sync_state、payload 五个稳定字段 ID。部署时核对文本字段和 UTC/北京时间解析；scope 使用排序后的完整店铺 ID，以逗号连接；checked_at 使用带时区的 ISO 时间。只展示回读确认的批次。分页中断、报告不同批、表格读取失败或同步不明时，保留独立来源和已确认范围。

可选链接绑定包含 table_url、link_source（[原明细 Base ID, 原明细 Table ID]）、link_shop_ids（该链接实际可见的完整店铺范围）和 views（已核实岗位视图的 HTTPS 链接）。只有回执中的来源标识匹配、查询范围与链接范围一致且成员有链接权限时才展示；钉钉侧仍须配置真实表格和视图访问权限。

## 发货看板

订单运行目录下的 ops-shipping-board.json 由试点部署维护。仅 enabled=true 时启用。tables 包含 board、orders_report，可选 shortages_report；各项使用现有订单后端 Table 约定的 baseId、tableId、profile、fields 和可选 url。主表使用店铺＋ERP NO 业务键。批次表使用上面五个字段；三者须分别绑定且属于同一组织 profile。原缺货明细同步继续沿用原绑定，缺货批次统计只在原明细回读通过后发布。全店铺缺货统计不拆成未经核实的单店缺货统计。

先在试点表核对四个岗位视图及已结束视图：

| 视图 | 优先字段与筛选 |
| --- | --- |
| 客服 | 网店单号、截止时间、紧急程度、售后、最近工序、揽收 |
| 操作 | ERP NO、待客审／待打印／已打印、库存风险、缺货及待入 |
| 库房打包 | 出库单、缺货、打包、各包裹与揽收 |
| 系统装机 | 出库单、配件、装机、系统测试 |
| 订单状态总览／已结束 | 在办按超时、截止时间、待核实排序；已结束按生命周期单独筛选 |

本版代码负责全量待发输入、按业务键补齐、逐包裹核验、保留已结束行和人工字段、回读后登记批次。现有顺丰后端查询需已授权，手机号后四位仅在原查询中使用，未进入批次或群回复。看板启用前应核对现有主表业务键和字段迁移；本地开发不创建或改写在线视图，也不触发现有同步。

## 试点顺序

1. 核对运营机器人接收程序、组织、群、成员和同机部署位置。先以隔离群验证真实 @、查询授权、关停功能、群回复回执与重复事件处理。
2. 核对订单环境已安装含 PR #5 的提交，再验收四种单号、完整后缀、跨店关联拒绝、登记异常、队列超时回读，以及定时巡检与原通知回归。
3. 核对发货主表、缺货表、前台明细与各自批次表的字段 ID、权限和四个岗位链接。验证真实多页、正常待发、历史行、人工字段与多包裹揽收，确认后再开放生产写入。
