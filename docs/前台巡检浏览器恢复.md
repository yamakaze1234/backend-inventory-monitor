# 前台巡检浏览器恢复

适用范围：本工具管理的独立 Chrome/Edge 店铺浏览器。旧扩展连接模式不自动重启。

## 较慢的页面处理节奏

- 自动采集从报表页开始，先核对原任务；已经在目标页面时复用当前页面。
- 报表等待期间只刷新报表页，不再为获取新状态往返商品页。
- 普通页面切换至少间隔 5 秒，报表刷新至少间隔 15 秒，成功点击至少间隔 1 秒。
- 页面、店名和控件连续三次就绪才继续，每次间隔 0.75 秒；最多等待 45 秒。刷新还必须确认新文档已产生，旧 DOM 不能冒充刷新后的数据。
- 数据完整性、店铺身份、商品数量、整机类目和 ERP 校验继续保留；放慢节奏不等于跳过校验。

## 崩溃恢复与导出任务

页面崩溃、页面断开、命令连接中断或超时会被识别。下载通道只监听当前巡检页；其他标签的崩溃不会触发本轮恢复。普通下载轮询暂时没有事件不算断线。

每轮最多恢复一次：检查浏览器 ID 归属，在当前店铺实例中替换巡检标签；实例已退出时使用本店原隔离目录重新打开。其他店铺窗口和日常浏览器不受影响。恢复后再次核对店铺身份。第二次故障停止本轮，保留历史库存；取消勾选或退出后不继续恢复。

点击最终“导出”前，以原子写入方式保存任务意向。即使点击已生效但连接中断，恢复后也只查询原报表，不重新提交。若 120 秒后仍未找到可唯一对应的报表，显示“导出提交结果未确认”，保留任务记录，等待人工核对。任务文件损坏或店铺不匹配同样停止，不按空任务处理。

最近 10 次运行记录继续每轮只记一条，包含恢复尝试次数、最终结果及通知状态。自动恢复不绕过新清单去重或在线明细回读条件。

## 验证与边界

在项目根目录设置 `PYTHONPATH=app/src;tests` 后执行：

```powershell
py -3 -B -m unittest discover -s tests -p 'test_douyin*.py'
py -3 -B -m unittest test_inventory_business test_inventory_browser_recovery
py -3 -B tools/verify_douyin_managed_recovery.py
py -3 -B tools/check_project.py
```

真实浏览器验证脚本使用两个全新、无登录的隐藏 Chrome 实例和本机测试页，主动使其中一个页面崩溃，核验页面及下载通道识别、当前页恢复、另一实例不变和原页刷新。不会访问抖店、提交官方报表、写 ERP 或发送群通知。测试目录位于 `.codex_tmp`，验收后按项目规则放入回收站。

这是巡检流程的规避与恢复措施，没有修补 Chrome 内核，也不代表原生 `StorageEstimate` 空指针故障已根治。候选包需要真实店铺巡检验收后才能确认业务端效果。
