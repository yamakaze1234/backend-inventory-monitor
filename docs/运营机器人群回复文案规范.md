# 运营机器人群回复文案规范

配套 [指令接口规划](运营机器人指令接口规划.md)。以下名称、编号、数量和时间均为示例，联调时使用接口回读值。

## 统一格式

- 第一行用「【功能｜结果】」，第二行给出商品或店铺与订单，随后给出数量、时间或下一步。查询简洁回复。写操作、任务和需要排查的错误附 `回执：{request_id}`。
- 接收端按指令、`status`、`code` 和业务结果选择模板。数量、原因和状态来自结构化字段。展示时间用北京时间 `MM-DD HH:mm`。订单号保留完整后缀。
- 数据缺失显示“未知”并附已知原因。真实 0 按 0 显示。价格使用人民币元和两位小数。库存附仓库和口径，历史快照附原采集时间。
- 订单统计标明单位。巡检优先展示去重后的订单数。后端只有商品明细行计数时，显示“明细行”。同一订单部分完成时归入待核对，已完成行数可单列。
- 同一群事件重复投递时，复用原业务回执并去重发送。用户主动查进度时按当时状态回复。一个任务默认发送一次入队回执和一次结果。临时查询不触发额外完成通知。

## 查询

**查询商品**支持完整 ERP 商品 ID 和名称、型号、SKU 关键词，兼容旧指令「查库存」，也支持「查询 5070 Ti 雪鹰库存和 ERP 价格」一类明确的只读问法。每项先列商品全称与 ERP ID，再列库存、ERP 价格、维护表价格。按 ID 查询单个商品且公司大库数据含待审扣减时：

```text
【库存｜查询结果】
示例配件｜ERP ID 56281
公司大库实际可销 7 件（ERP 可销 18 件，待审 11 件）
采集时间 11-11 16:39
ERP 库存成本 ¥365.00/件（公司大库，读取于 11-11 16:41）
主机维护表配件单价 ¥370.00/件（店铺A · 示例整机）
```

关键词命中多件商品时，按相同顺序逐件列出。维护表只有整机到手价时，在店铺和配置名后展示该配置的价格。

```text
【库存｜关键词查询结果】
5060 Ti 白色 · 匹配 2 件

示例 5060 Ti 16G 白色｜ERP ID 56281
公司大库实际可销 7 件（11-11 16:39）
ERP 库存成本 ¥3,650.00/件（公司大库，11-11 16:41）
主机维护表整机到手价 ¥6,999.00（店铺A · 示例配置A）

示例 5060 Ti 8G 白色｜ERP ID 56282
公司大库实际可销 0 件（11-11 16:39）
ERP 库存成本 ¥3,150.00/件（公司大库，11-11 16:41）
主机维护表价格：未找到关联配置
```

结果超过 5 件时追加“共匹配 {total} 件，本次显示 5 件，可补充关键词或按 ERP ID 查询”。同一配件有多条维护表价格时，逐条列出店铺、配置和价格类型。超过 3 条时标明总数并提示指定店铺。没有匹配商品时回复“【库存｜未找到】未找到匹配商品，请补充名称、型号、SKU 或完整 ERP ID”。

固定脚本有可靠匹配时直接用查询结果模板。AI 辅助后经脚本确认结果时，可以在标题后加一行“按「5060 Ti、白色、16G」查询”，正文沿用商品、库存和价格格式。简称可能对应多个型号、条件无法核实时，回复“【库存｜请确认型号】请补充显存、品牌或 ERP ID”，并只列目录中已核实的候选商品名称和 ERP ID。AI 超时或不可用时沿用脚本已核实结果，或提示补充型号。

ERP 成本读不到时显示“ERP 库存成本：未知”。维护表按实际情况显示“未绑定维护表”“未找到关联配置”“价格列未核实”或“读取失败”。保留本次已确认的其他数据。

指定分库时将数量标签改为该库对应的“实物库存”或“可销库存”。缺少数据时使用以下模板。已有旧快照时附其原采集时间及数据状态。

```text
【库存｜数据未知】
示例配件（ERP 56281）· 示例仓库
本轮未取得该仓库库存，当前数量未知。
```

**查价格变化**，结果来自已完成的成本检测批次：

```text
【成本变化｜查询结果】
示例配件（ERP 56281）· 公司大库
¥350.00 → ¥365.00（+¥15.00）
检测时间 11-11 16:30
```

无匹配记录且有完成批次时回复“本批次未发现该商品的成本变化”。没有已完成批次时回复“暂无已完成的成本检测批次”。超过展示条数时追加“共 {total} 条，本次显示 {shown} 条，可按 ERP 商品 ID 查询”。

## 订单状态查询

默认按网店单号查，回复保留完整网店单号及后缀。使用其他入口时，对象行按实际入参显示“ERP NO 单号”“出库单号”或“物流单号”。先给出最近有明确时间的业务记录，再按发生时间逐条列出步骤和对应单号。关联多张订单时显示数量，用“关联订单最近记录”。重复发生的步骤分别保留，时间未知时显示“时间待核实”。所有记录时间均未知时用“最近状态待核实”。操作人按群权限展示。

```text
【订单状态｜查询结果】
网店单号：123456789012345A-1
最近记录：打包（11-12 09:50）
订单记录
11-12 09:10　装机　CK-示例
11-12 09:35　系统测试　CK-示例
11-12 09:50　打包　SF示例
```

| 场景 | 群回复 |
| --- | --- |
| 已找到订单但无记录 | 【订单状态｜暂无记录】已找到关联订单，暂无可展示的业务记录。 |
| 找不到单号 | 【订单状态｜未找到】在已查询范围内未找到关联订单，请核对单号、店铺及订单同步状态。 |
| 网店单号命中多店或拆单不明确 | 【订单状态｜请确认订单】请补充店铺或提供带完整后缀的网店单号。 |
| 类型或参数缺失 | 【订单状态｜请补全单号】发送「查订单状态 完整网店单号」。也支持 NO-、CK- 或「查订单状态 物流 完整物流单号」。 |
| 关联订单超出店铺权限或范围无法核实 | 【订单状态｜无法展示】当前无法确认该单号在本群可查询的店铺范围内。 |
| ERP 或登记读取失败 | 【订单状态｜暂不可用】本次未能完整读取订单记录，请稍后查询。附回执编号。 |

## 发货监控汇总

```text
【发货监控｜在线汇总】
范围：店铺A、店铺B
检查时间 11-12 10:30
待发扫描 26 单｜已超时 2 单｜48 小时内到期 5 单
截止待核实 1 单
缺货配件 3 种｜库存待核实 1 种
点击表格查看明细：{授权后的订单状态总览链接}
岗位视图：客服｜操作｜库房打包｜系统装机
缺货配件：{授权后的缺货配件表链接}
```

待发、超时、紧急和截止待核实使用“单”，缺货或库存待核实配件使用“种”。若展示配件明细，按已核实缺口排序，附 ERP 商品 ID 和缺口件数。待入数量另列，缺失时标为未知。汇总沿用报告的检查时间与店铺范围。

“点击表格查看明细”打开订单状态总览，可从表内切换岗位视图。已配置且授权时，岗位名称可直接链接对应视图。订单表按网店单号查找，显示 ERP 当前状态、各工序记录、物流核验及人工处理状态。群回复附总览与缺货表入口，订单状态以表内核对时间为准。订单明细或工序仅部分同步时，标题用“【发货监控｜部分数据】”，注明对应来源和已核实范围。

| 场景 | 群回复 |
| --- | --- |
| 无匹配范围的报告 | 【发货监控｜暂无汇总】钉钉 AI 表格暂无 {店铺范围} 的已核实汇总。 |
| 已有报告但部分读取异常 | 【发货监控｜部分数据】以下为本轮已核实范围。{店铺或数据来源}待核实。随后显示检查时间和已确认的数量，未知项标为“待核实”。 |
| 报告完整且无待发订单 | 【发货监控｜无待发订单】{店铺范围} 本轮扫描 0 单。附检查时间。 |
| 读取报告失败 | 【发货监控｜暂不可用】本次无法读取钉钉 AI 表格，请稍后查询。附回执编号。 |

发货订单表和缺货配件表使用不同批次时，各显示对应的检查时间。某张表同步失败或状态未知时写明表名和状态。可展示上次已核实数据时附原时间，并注明“本轮同步待核实”或“本轮同步失败”。表格未绑定时回复“【发货监控｜表格未绑定】请联系管理员配置发货监控 AI 表格”。

## 前台库存监控

```text
【前台库存｜在线监控明细】
店铺A · 平台快照 11-12 10:20
待处理 2 个 SKU
示例整机A · 配置A｜平台库存 0 件｜配件齐全｜待补库存
示例整机B · 配置B｜平台库存未知｜SKU 待核对
钉钉 AI 表格：{授权后的监控明细入口}
```

平台快照和配件核对时间不同则分别显示。筛选到具体 SPU 或 SKU 时在对象行标明完整编号。在线表没有对应行时回复“【前台库存｜暂无监控记录】该店铺或 SKU 暂无在线监控记录”。有部分同步异常时回复“【前台库存｜部分数据】以下为已回读核实的监控记录”，附批次时间及异常范围。表格未绑定或读取失败时分别提示“表格未绑定”或“暂不可用”，读取失败附回执编号。

## 添加监控

```text
【添加监控｜已保存】
示例配件（ERP 56281）· 公司大库实际可销
低库存阈值 5 件，监控已启用，提醒项：{已启用提醒列表}
回执：{request_id}
```

只有配置回读一致时使用“已保存”。库存尚未采集时可补一句“库存将在后续采集后显示”。重复添加时用：

```text
【添加监控｜已关注】
示例配件（ERP 56281）· 公司大库实际可销
当前阈值 5 件。可发送「修改监控阈值 56281 为 10」。
回执：{request_id}
```

## 修改监控阈值

```text
【修改监控阈值｜已保存】
示例配件｜ERP ID 56281
公司大库实际可销｜低库存阈值 5 件 → 10 件
回执：{request_id}
```

已回读一致时使用“已保存”。原阈值已经等于目标值时回复“【修改监控阈值｜已是目标值】{商品}｜ERP ID {goods_id}，当前阈值 {threshold} 件”。未关注时回复“【修改监控阈值｜未关注】请先添加该商品的库存监控”。已停用的配置可显示“当前监控已停用”。只有收到实际投递回执时才报告提醒已发送。

## 匹配与巡检

```text
【订单匹配｜已入队】
店铺A · 网店单号 123456789012345A-1
执行结束后回复结果。
回执：{request_id}
```

巡检用“【订单巡检｜已入队】”，对象行用店铺和实际巡检范围。进度查询继续显示回执和对象，按状态替换标题与正文：

| 状态 | 标题 | 正文模板 |
| --- | --- | --- |
| `queued` | 已入队 | 任务已排队，等待执行。 |
| `running` | 执行中 | 任务正在执行，可用回执查询进度。 |
| `completed` | 已完成 | 已匹配 {成功数} 单，已有有效关联跳过 {跳过数} 单。 |
| `completed` 且无待处理对象 | 已完成 | 本次未发现待匹配订单。 |
| `needs_review` 且部分完成 | 部分完成 | 已匹配 {成功数} 单，跳过 {跳过数} 单，{待核对数} 单待核对。原因：{可公开原因}。 |
| `needs_review` 且无已匹配对象 | 待核对 | {待核对数} 单待核对。原因：{可公开原因}。 |
| `failed` | 执行失败 | {已确认的失败原因}。{可执行的处理方式}。 |
| `unknown` | 结果待核对 | 执行结果尚未确认，请按原回执查询，暂勿重复提交。 |

指定订单的最终回复优先用“已匹配并回读确认”或“已有有效关联，已跳过”。仅有明细行统计时，改用实际单位和数量。用户查询进度时可追加“最终回复：已投递 / 待发送 / 投递失败 / 投递状态待核对”。该字段取原任务最终回复的投递状态。

## 参数和权限提示

| 场景 | 群回复 |
| --- | --- |
| 未识别指令 | 【指令｜未识别】发送「帮助」查看本群可用指令。 |
| 添加监控缺少阈值 | 【添加监控｜缺少阈值】请补全指令，例如「添加监控 56281 阈值 5」。 |
| 修改阈值缺少编号或阈值无效 | 【修改监控阈值｜请补全参数】请提供完整 ERP ID 和非负整数阈值，例如「修改监控阈值 56281 为 10」。 |
| 商品或店铺不唯一 | 【{功能}｜请确认对象】找到多个符合条件的对象，请提供完整 ERP 商品 ID、SKU 或店铺编号。仅列出授权范围内的候选。 |
| 授权范围内未找到 | 【{功能}｜未找到】请核对{ERP 商品 ID / 回执编号}后再查。 |
| 越权 | 【{功能}｜权限不足】当前群或账号无法使用这条指令。 |
| 软件设置里取消了此功能 | 【{功能}｜本群未启用】当前群未开启此功能，请联系管理员在软件中开启。 |
| 请求编号冲突 | 【{功能}｜回执冲突】本次请求与原回执参数不一致，请联系管理员核对。 |
| 执行前确认订单服务未启动 | 【{功能}｜服务未启动】订单服务当前不可用，请联系管理员检查后再提交。 |
| 查询服务暂不可用 | 【{功能}｜暂不可用】暂时无法读取数据，请稍后查询。 |

帮助按软件保存的群功能勾选项生成，只列本群已启用、当前可用且成员有权限使用的指令，每项说明用途、给出可复制的指令，并标注适用的可选参数和数据口径。帮助已启用但没有可用业务指令时，回复“【运营机器人｜帮助】本群暂无可用业务指令，请联系管理员检查群功能设置”。帮助被取消时，其他提示也省略“发送帮助”引导。以上错误提示按实际失败字段选择对应对象，群回复使用可公开的业务原因。

验收时逐条核对模板状态与接口回执，重点覆盖固定脚本和 AI 辅助后的结果、真实零库存、未知库存、已有关注、仅入队、部分完成、执行未知和回复投递未知。订单状态查询核对默认网店单号及其他三种单号标签、最近记录、重复步骤、暂无记录及查询失败。发货汇总核对总览链接能打开对应店铺的状态表、岗位视图和缺货配件入口。发货汇总和前台库存监控均核对原检查时间、部分数据及各表同步状态。核对中文换行、时间、单位和完整单号。
