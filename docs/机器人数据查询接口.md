# 机器人数据查询接口 v1

本地候选提供统一查询接口和标准库 CLI，未来机器人可以直接读取业务数据，不需要模拟页面点击。尚未部署新的机器人、发送消息或修改价格。ERP 调价单因当前账号无权限且用户取消接入，不提供查询入口；“价格变动”来自公司大库成本检测快照，不等同于 ERP 调价单。

## 连接与权限

服务只监听 `127.0.0.1`，每次进程启动生成新的令牌。现有桌面会话通过 `GET /api/data/connection` 取得 `{url,token,scope:"read-only",expires:"process-exit"}`，部署集成时由已授权宿主将这个只读连接交给机器人。不要把桌面的完整操作令牌交给 AI。只读令牌仅支持以下接口，不能启动匹配、保存业务配置、发送提醒、安装更新或取得完整会话权限。

所有请求使用 `X-Console-Token` 请求头；POST 使用 `Content-Type: application/json`。不把令牌放到 URL、命令参数、日志或仓库中。本机 Host 和 Origin 仍需符合现有工作台校验。程序重启后需重新交接连接。

| 接口 | 用途 |
| --- | --- |
| `GET /api/data/catalog` | 返回版本、数据集、字段白名单、时间字段、筛选操作和价格刷新能力 |
| `POST /api/data/query` | 查询已保存或已采集的数据，不触发 ERP 读取或业务写入 |
| `POST /api/data/refresh` | 仅接受 `price_changes`，显式读取 ERP 成本并更新本地检测记录，不发送提醒、不修改 ERP |
| `GET /api/data/job?id=...` | 查询上一步价格任务状态；不能读取其他业务任务 |

## 数据集

| 数据集 | 业务内容 |
| --- | --- |
| `inventory` / `products` / `erp_catalog` / `coverage` | 配件库存、关注配置、已采集目录、逐商品检查覆盖 |
| `inventory_events` / `messages` | 库存提醒历史、已归档关联的货源消息 |
| `orders` | 订单巡检匹配任务，保留完整订单编号与店铺身份 |
| `shops` / `douyin_stock` / `douyin_events` | 前台店铺、整机 SKU 库存、变化历史 |
| `restock_records` / `exclusions` / `low_stock_rules` | 补库存历史、排除链接、按店铺的预警规则 |
| `price_changes` / `price_affected_configs` / `price_batches` | 配件前后成本、受影响配置、完整检测批次历史 |
| `price_results` / `price_events` / `price_configs` | 全部成本检测历史、提醒历史、绑定配置及实际配件清单 |
| `robots` / `notification_receipts` / `monitor_sources` | 机器人公开状态、投递回执、货源监听对象 |
| `reports` / `daily_status` | 已生成周报正文、定时日报计划与最近结果 |
| `connection_status` / `update_status` | 库存连接状态、软件更新状态 |

字段以目录响应为准，共 27 个数据集。未提供 Cookie、Webhook、数据库密码、AI Key、SQL 来源指纹、浏览器资料、任意文件读取或任意 SQL。库存数量未知返回 `null`，不能按零处理。前台库存中的 `erp_parts`、`erp_shortages`、`erp_unknown`、`erp_checked`、`erp_warehouse` 分别表示配件、缺口与待入、未核实原因、核实时间和仓库，不能混用平台库存与 ERP 库存。

## 查询协议

```json
{
  "dataset": "price_changes",
  "filters": [{"field":"goods_id","op":"eq","value":"123"}],
  "page": 0,
  "page_size": 50,
  "comparison": "batch"
}
```

支持 `query` 全文字查询；`filters` 最多 20 项，按 AND 组合。操作为 `eq`、`ne`、`contains`、`in`、`gte`、`lte`、`is_null`。精确身份查询使用 `eq`，不要依赖名称或全文模糊匹配。`in` 最多 100 个值。`sort` 形如 `{"field":"created","direction":"desc"}`；字段和方向均校验。

分页从 0 开始，每页 1–200 条。返回 `total`、`has_more`、`snapshot` 和 `rows`。后续页带回 `snapshot`；数据变化时返回 `SNAPSHOT_CHANGED`，从第一页重新读取，避免漏行或重复。单个数据源超过十万条时返回 `SOURCE_LIMIT`，不以截断结果冒充完整数据。界面的历史下拉仅列最近 100 批，但 `price_batches` 接口查询完整历史后再分页和筛选。

`start` / `end` 作用于目录中的 `time_field`，接受 ISO 日期或时间；不带时区按北京时间。开始包含，结束时间不包含；仅填结束日期时包含该日全天。无时间字段的数据集不接受时间筛选。价格视图支持 `comparison: batch/day` 和可选 `run_id`。`day` 表示该批次与前一自然日最后有效采集比较，前一日无记录时保持未知，不拿更早数据冒充昨日。

价格字段以整数分表示，`before_cents` / `after_cents` 为单个配件前后成本，`delta_cents` 为单价变化。`price_affected_configs.cost_delta_cents` 按本批次保存的实际 BOM 数量汇总变化；历史记录未保存数量时为 `null`，不猜数量。配置身份是 `shop_id + config_id`。这些值不是整机完整成本或利润，也不会写入到手价。

```json
{"dataset":"orders","filters":[{"field":"shop","op":"eq","value":"76"}],"start":"2026-11-08","end":"2026-11-08","sort":{"field":"created","direction":"desc"},"page":0,"page_size":50}
```

显式更新成本：

```json
{"dataset":"price_changes","request_id":"调用方生成的唯一请求编号"}
```

提交到 `/api/data/refresh` 返回 `{job}`，随后轮询 `/api/data/job?id=...`，确认 `done` 后查询价格数据集。`failed` 时读取错误信息，不把入队视为完成。相同请求编号重试不会重复执行；编号长度 8–80。更新本地成本基准用于下次比较，但不消耗定时提醒锚点，不改定时检查时间，不生成或投递提醒。其他数据集本轮没有新增自动刷新动作，按各自已有业务采集流程更新。

查询错误返回 `code` 和 `error`：包括 `UNKNOWN_DATASET`、`INVALID_QUERY`、`INVALID_FILTER`、`INVALID_PAGE`、`INVALID_TIME`、`INVALID_SORT`、`SNAPSHOT_CHANGED`、`SOURCE_LIMIT`、`SOURCE_UNAVAILABLE`。鉴权失败为 HTTP 403。异步任务沿用业务任务状态协议。

## CLI

候选目录附带 `query_inventory_data.py`，只依赖 Python 标准库。由部署方通过环境变量注入只读令牌，例如 `INVENTORY_QUERY_TOKEN`；下面命令不包含令牌值。

```powershell
python query_inventory_data.py --url http://127.0.0.1:端口
python query_inventory_data.py --url http://127.0.0.1:端口 --request query.json
python query_inventory_data.py --url http://127.0.0.1:端口 --refresh
python query_inventory_data.py --url http://127.0.0.1:端口 --job 返回的任务编号
```

CLI 禁用代理与重定向，只访问本机固定端点。部署机器人时可以直接包装这些接口为工具。数据接口本身不会解析自然语言、自动发送群消息或自动调整售价；自然语言映射、提醒接收对象及调度仍由后续机器人部署实现。


## 维护表价格巡检

`price_schedule` 只读返回巡检开关、通知开关、计划模式、北京时间固定时刻、下一次执行时间、来源类型和读取状态，不返回本机文件路径。`price_configs` 返回维护表中的店铺、SPU（product）、SPU:SKU（config_id）和配件 ID、数量；每次巡检重读已保存的维护表，身份或数量异常时停止本轮采集，旧结果保留时间标记。

`price_changes` 新增 `band` 和 `percent`：`high` 为上涨 ≥5% 或从零上涨，`up` 为上涨 <5%，`down` 为降价，`same` 为未变化，`first` 为首次采集，`missing` 为价格缺失。百分比不能计算时为 null；金额仍以整数分返回。可用 filters 精确筛选 band。以上展示分类与现有累计 100 元通知阈值相互独立。

补库存通知在在线明细同步并回读确认后才发送；同步失败保留待发状态，恢复后不重复发送已成功或结果未知的消息。
