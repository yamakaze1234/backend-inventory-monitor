# 日报配置与升级保留（候选实现）

## 源码与运行链路

主线基线：19ef6d9。分支：codex/daily-report-config。

设置表单 `app/src/daily_report_business.py` → 工作区 `daily-report.json` →
`integrations/order_backend/control/report-server.mjs` → `report.mjs` →
`mcp-client.mjs` → DBX 只读 MCP → 固定项目组查询 → 完整性校验 → openpyxl/HTML。

现用包只读取明确的两个源码文件（report.mjs、mcp-client.mjs）作为移植起点；未复制运行目录、数据库、密钥、队列、原日报或 node_modules。
原专有工作簿生成依赖已替换为项目锁定的 openpyxl；本机 DBX、Node、Python 由用户选择，不包含在兼容源中。

## 配置契约

工作区由 ORDER_BOT_CONFIG 的父目录定位；未设置时使用部署生成的 order-department.json 指针。不依赖当前目录。

`daily-report.json` v1 严格字段：version、connectionId、connectionName、database（ERP）、networkMode（direct）、dbxExecutable、dbxData、python。
没有预置生产账号或服务器地址。ID 来自 DBX 的公开 dbx_list_connections 接口；每次任务核对 ID 与名称，查询 ID 和连接名称白名单采用同一任务快照。
数据库、视图、统计项目组均固定，连接选择不能扩大报表范围。连接重命名或删除需要重新绑定。

界面先填写运行路径，再从公开元数据选择连接，显示名称、服务器和端口。账号及服务器地址仍在 DBX 管理。
保存不重启机器人；运行中的任务保留快照，新任务重新读取配置。配置缺失、损坏、未知版本均失败关闭。

保存使用 SQLite 跨进程写锁、原文件备份、fsync 和原子替换；失败保留活动文件。版本 1 为首次格式，未知版本拒绝导入，不猜测升级。
配置导入同样校验，禁止未知字段（包括密码）。新机仅导入公开引用；本机路径和 DBX 凭据需自行重新配置，成功测试之前不能视为迁移完成。
