# 新机修复包 v1.11

适用于已使用旧版“一体迁移包”的电脑。修复直接打开 EXE 后显示空配置、订单后端仍发送旧版发货长消息的问题，同时安装本轮发货监控、揽收核验和 ERP 调价汇总。

1. 将修复 ZIP 解压到独立文件夹，不要覆盖原迁移包文件夹。
2. 在原程序停止订单服务，等待任务完成，再右键托盘选择“退出程序（同时停止钉钉监控）”。
3. 将原一体迁移包根目录拖到“一键修复.cmd”上。该目录应包含 `inventory`、`robot`、`settings`；也可以双击脚本后输入这个目录。
4. 看到修复结果 `version: 1.11`、`backendCurrent: true` 后，直接打开原来的库存 EXE。旧文件名保留，原桌面快捷方式和“一键部署启动”入口仍有效。

修复读取原 `device-paths.json` 和 `order-bot.json`，不导入作者的配置，不迁移或清空数据库，不改变计划开关，不自动启动机器人。原 EXE 的备份保存在同目录的 `.before-时间` 文件，后端备份保存在原工作区 `order-backend-backups`。结果写入原 EXE 旁的 `repair-result.json`。

如果提示服务仍在运行、任务待核验、路径失效或队列属于其他工作区，先解决具体问题再重试，不要删除配置后重新部署。只想检查时，可使用原包 PowerShell 7 执行 `tools/repair_new_machine.ps1 -PackageRoot 原包目录 -CheckOnly`。

物流删除规则保持：全部包裹真实确认揽收，且删除前再次核对运单和在线记录身份一致，才删除对应在线行。打包、打印或空路由不会触发删除。顺丰凭据和 `tiny_tools` / `sf` 运行依赖沿用新机现有配置；修复包不包含任何凭据，也不自动安装外部 SDK。未配置或查询失败时保留订单。

本包只修复已有一体包，不是从零安装的完整订单匹配系统。已配置在线表的同步继续使用原表和原开关；尚未绑定的电脑不会自动绑定作者的表。
