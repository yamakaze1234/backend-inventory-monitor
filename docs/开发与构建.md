# 开发与构建

本文件是本仓库开发与 PR 流程入口；发布产物和更新通道要求见 [发布边界](PUBLICATION.md)。

## 准备开发环境

在 Windows x64 上检出完整源码，使用 PowerShell 7。一键准备开发环境：

```powershell
./tools/一键部署环境.cmd -Mode Development
./tools/一键部署环境.cmd -Mode Development -CheckOnly
```

开发模式检查 PowerShell、WebView2、Node.js、uv（至少 0.12.3），由 uv 按 `.python-version` 准备 Python 3.13.6，并以 `uv sync --locked` 将锁定依赖安装到项目 `.venv`，并在 `app/web` 执行 `npm ci`。运行版用户不需要开发模式。脚本不会安装完整外部订单工程，也不登录 DWS、ERP 或店铺。

手动准备可使用：

```powershell
winget install --id astral-sh.uv --exact --source winget
uv sync --locked
npm --prefix app/web ci
```

`dev.ps1` 的 Python 操作和直接打包入口都会先执行 `uv sync --locked`，再使用 uv 返回的项目解释器。`-PythonExecutable` 仅作为 uv 选择基础 Python 的参数，不能绕过项目依赖同步。已构建 EXE 和纯前端操作不要求 uv。

`pyproject.toml` 是依赖声明的唯一来源，`uv.lock` 锁定直接及传递依赖；目前解析目标为 Windows x64、Python 3.13。程序显示版本仍由 `inventory_version.py` 决定。前端继续使用 npm 与 `package-lock.json`。

新增依赖用 `uv add 包名`，开发依赖用 `uv add --dev 包名`；升级指定依赖用 `uv lock --upgrade-package 包名`，审核锁文件差异并重新验证。普通运行使用 `--locked`，锁过期会失败，避免悄悄修改依赖。`-CheckOnly` 使用离线只读检查，不安装 Python 或依赖。

旧 requirements 文件仅保留兼容导出，不手改。依赖变更后执行：

```powershell
uv export --locked --no-dev --no-emit-project --no-hashes -o requirements.txt
uv export --locked --no-emit-project --no-hashes -o requirements-build.txt
```

uv 行为依据：[官方锁定与同步说明](https://docs.astral.sh/uv/concepts/projects/sync/)。

## 开发与本地验证

```powershell
./dev.ps1 Check
./dev.ps1 Test
./dev.ps1 WebBuild
./dev.ps1 WebPreview
```

`WebPreview` 使用独立样例数据。运行真实业务之前先核对数据目录、账号和所启用的计划，避免把开发启动当作隔离验收。新增或修改代码添加解释目的的中文注释；测试围绕行为和风险，不为可逆的小改动重复实现本身。

涉及更新流程时，执行 `tools/verify_update_helper.ps1` 及相关更新测试；涉及打包时，从当前源码重新构建并执行对应包验收。记录本轮命令、结果、候选哈希和未验收部分。本地测试不表述为服务器 CI，模拟账号或隔离数据不能证明真实业务链路已通过。

## 构建

```powershell
./dev.ps1 Build -OutputDirectory outputs/release-candidate
```

DWS 默认从当前用户的 `.local/bin/dws.exe` 读取，也可明确指定：

```powershell
./tools/build_inventory_monitor.ps1 -PythonExecutable ./.venv/Scripts/python.exe -DwsPath C:/Tools/dws.exe -OutputDirectory outputs/release-candidate
```

Windows 桌面宿主使用 .NET Framework 4.x 的 `csc.exe`。构建脚本从 NuGet 获取固定版本 WebView2 SDK 并核对摘要；离线可为 `tools/build_console_host.ps1` 指定 `-WebView2AssetsRoot`，目录内提供所需 SDK DLL。普通运行端安装的 WebView2 Runtime 与构建用 SDK 不同。

打包入口核验资源与模块，生成构建清单和产物摘要。包内提供程序、一键部署环境入口、使用说明、结构图及第三方许可。业务数据、浏览器登录、连接配置和签名私钥不属于构建输入。

## 功能分支与 PR

1. 核对仓库根目录、远端、最新主线、当前分支、未提交改动及其他工作树。保留其他任务的内容；并行开发需要隔离时使用独立工作树。
2. 从核对过的主线创建明确范围的 `codex/功能名` 分支，按本次需求修改和本地验证。只提交相关源码、测试和文档，不整体暂存工作目录。
3. 按已有授权推送功能分支并在 Gitea 创建或更新 PR。推送前检查现有 CI/CD 触发条件；默认不新增或启用 Actions，也不擅自关闭已有流程。
4. PR 写明问题、实际行为变化、验证命令与结果、未验收项和发布状态。范围变化时同步更新标题和正文，处理审查意见后仅重跑受影响检查。
5. 合并、发布和替换现用程序分别按明确授权执行。合并后从确定提交构建，或核验已有产物确实对应该提交，完成附件及更新通道回读后再记录发布结果。

“推送或建立 PR”不等于获准合并、发布或安装。一次性的本机直改约定不作为后续开发的默认流程。现用数据和发行附件保持在源码版本控制之外。
