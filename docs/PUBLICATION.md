# 发布边界

## 公开源码与发行包

公开源码包含应用、前端、订单兼容层、测试、环境部署与构建脚本、文档和第三方许可。默认连接与通知对象使用空配置或示例。

发行包从确定源码构建，包含 EXE、一键部署环境脚本、使用说明、结构图、必要采集脚本、许可及构建校验记录。数据库、维护表、业务导出、机器人接收配置、浏览器资料、账号、密钥和本机备份不进入公开仓库或发行包。更新签名只发布公钥，私钥由发布者在仓库外保管。

通用版保留同 ERP 字段适配及库存口径，部门自行配置工作区和账号。完整订单匹配系统是外部依赖，不能将兼容层描述为整套订单工程。

## 更新通道

`app/src/inventory_version.py` 是应用版本的唯一入口。正式版本标签和附件对应确定提交，已有版本标签不覆盖。每次发行记录版本、提交、构建清单、文件大小及 SHA-256。

客户端优先读取 Gitea `inventory-updates` 发行中的 `inventory-update.json`，失败时尝试代码中配置的 GitHub 备用源。只有实际发布并回读过的源才可声明可用；配置了备用 URL 不等于已完成双源发布。

更新清单由 `tools/prepare_update_manifest.py` 离线签名，声明应用、平台、版本、下载地址、大小、摘要及更新说明。公钥打包在 `app/ui/update-public-key.txt`。旧客户端需要使用受信公钥验证清单，发布时不能无迁移方案地更换公钥。

本轮首次启用正式通道，v1.07 内置新的发行公钥。此前 v1.06 候选内的试验公钥不能验证新通道，首次需要通过已核验的完整安装包或本机安全替换升级；此后保持同一发行公钥。不能将 v1.06 的检查失败表述为“已经是最新版”。

客户端验签及下载校验成功后，由用户点击安装并重启。自动检查不代表自动安装；源码模式不替换 Python。安装只替换当前 EXE，业务数据保持原位，完整外部订单工程不随 EXE 更新。

## 发布验收

1. 按 [开发流程](开发与构建.md#功能分支与-pr) 完成范围核对、验证、提交及 PR；按已有明确授权合并发布。
2. 从确定提交构建，核对包内容和隐私边界。验收首次启动、离线样例、相关业务回归、更新替换和失败处理，保存本轮结果。
3. 上传正式版本附件并从实际下载地址回读，核对哈希、大小和版本。需要双源时使用同一份产物并分别核验。
4. 发布签名更新清单，再使用客户端同一验签路径读取远端清单，并检查下载与当前版本判断。先有可验证附件，再更新通道。
5. 获准更新本机时，核对现用路径与数据目录，安全安装并检查启动回执、实际版本及业务状态。附件可下载、更新通道可用和本机安装成功分别记录。

本地和模拟验收不代表真实 ERP、店铺账号或通知投递已验证。无确认回执时保留“待核验”状态，先查实际结果，避免重复发布或重复业务操作。

## 恢复与维护

更新前保留原 EXE 恢复文件；新版已退出且启动未确认时助手尝试恢复旧版。新版仍存活但未给出健康回执时不强杀业务，需核对后处理，详见 [使用说明](使用说明.md#更新与恢复)。

收尾只清理本轮确认无用的临时产物，优先移入回收站；保留当前正式包、发行记录和必要恢复文件。运行数据不按构建缓存清理。库存监控发布不自动继承其他项目的群通知授权。
