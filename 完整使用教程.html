01 · 先判断这台电脑能否使用

本说明对应：桌面正式版 v1.01“本机自动重登版”，采集脚本 0.4.0。核对日期：2026-09-13。相同 v1.01 名称的早期包不一定包含本机重登功能，以库存页是否存在“自动重登（无人值守）”开关为准。

环境本版本结论使用建议
Windows 11，Intel/AMD 64 位当前已实测环境推荐用于部署；仍需本机完成首次配置和验收
Windows 10，Intel/AMD 64 位尚未完成整套程序实测不能按“已验证支持”交付；先测程序、浏览器、重登及机器人
Windows 7当前包不支持不能靠安装一个旧 Python 修复；EXE 自带 Python 3.13
Windows 8 / 8.1不列入支持范围浏览器及自动重登依赖组合未适配
Windows 32 位当前 64 位包不支持需要单独构建与验收，当前未提供
Windows ARM64 / Windows Server未验证不承诺兼容或后台会话运行
macOS / Linux当前 Windows EXE 不支持未提供对应安装包

开发电脑已测：Windows 11、Python 3.13.6 打包运行时、Node.js 24.16.0、OpenCLI 1.8.6、Chrome OpenCLI 扩展 1.0.24。版本记录表示实测组合，不表示必须使用相同 Chrome 版本，也不代表未来任意升级都兼容。

硬件没有测定严格最低值。部署建议：8 GB 或更多内存、预留至少 1 GB 磁盘并为日志和历史留出增长空间，使用 SSD；推荐 1920×1080 显示环境。高缩放或小屏出现按钮被遮挡时，调整窗口与显示缩放。此处是使用建议，不是性能保证。

系统依据：Python 3.13 官方 Windows 说明 ↗；Chrome 官方系统要求 ↗。Python 3.13 的官方基础范围包含 Windows 8.1 及更新系统，但不能据此推导本程序的全部依赖在这些系统上都可用。

03 · 从下载包到第一次打开

  1. 把完整 ZIP 解压到长期保留、当前 Windows 用户可写的文件夹，例如 D:\库存监控。不要在 ZIP 内直接双击运行，不要放进临时目录或每次自动清空的位置。
  2. 核对包内有正式版 EXE、inventory-erp.user.js、本 HTML 教程、inventory-setup.md、SHA256SUMS.txt 和构建记录。
  3. 双击 后台库存监控_正式版_v1.01.exe。不需要先安装 Python，不需要运行源码，也无需为了库存监控先做钉钉“一键配置”。
  4. 首次可能显示“等待 ERP”，这是尚未建立采集连接，不等于程序损坏。先按下一节完成 ERP 配置。
  5. 同一电脑只保留一个正式版进程监听库存端口。提示“已有库存程序运行”时，从旧程序托盘退出后再开新版。

可选校验：在文件夹打开 PowerShell，执行 Get-FileHash -Algorithm SHA256 '.\后台库存监控_正式版_v1.01.exe'，与 SHA256SUMS.txt 中同名文件记录对照。哈希用于确认文件是否与该包一致，不替代来源判断。

04 · ERP 和脚本首次配置（必须手动一次）

  1. 安装 Chrome 和 ScriptCat。已有其他 ERP 脚本时，保留它们；本脚本名称是“公司大库重点产品采集”，不要覆盖独立的 3cerp-js。
  2. 用文本编辑器打开包内 inventory-erp.user.js，复制全部内容。在 ScriptCat 新建脚本并粘贴、保存；升级时打开原来的同名脚本覆盖内容，不要重复安装多个同名副本。确认元数据版本为 0.4.0。
  3. 启用脚本。在 Chrome 中登录 ERP ↗。需要无人值守重登时，让 Chrome 保存并自动填充账号密码；首次输入密码由你自行完成。
  4. 依次打开“库房管理 → 分库库存”。在库房下拉框选择“公司大库”，点击左侧库存列表旁的“搜索”，不要点右侧分库库存账的搜索。
  5. 点击右下角库存采集按钮，输入 ERP 顶栏显示的账号姓名。这是核对库存范围用的可见名称，不是密码，也不一定是登录账号字符串。
  6. 在桌面程序点击“立即检查”。等待最近成功检查时间更新，再搜索商品。如果只看到“已连接”，只说明已建立通信；完整库存快照成功才算完成初次采集。

不要关闭分库库存标签。它存在时可以切到其他 ERP 功能页，程序不会把当前页面强制切回库存。首次连接后变更 ERP 账号或仓库会被拒收；需要重新核对连接范围，不能混用两个账号的数据。

05 · 添加产品、配置阈值与日常操作

  1. 打开“添加商品”，选择 goodsid 精确搜索或名称模糊搜索。goodsid 是 ERP 商品编号，不等于 SKU。没有搜索结果时，先确认完整目录采集成功。
  2. 双击正确商品，核对名称、规格、真实 SKU、商品编号、分类及预警值。名称相似时不要只凭型号中的一个数字选择。
  3. 默认按公司大库可销数预警。若要监控指定分库实际库存，按上文“产品分库特例”刷新并选择真实仓库。
  4. 设置要接收的库存事件，保存配置。列表中的数字来自最近成功快照，不是实时推送的 ERP 数量。
  5. 上班时可保持“自动重登（无人值守）”关闭，正常采集不受影响；掉线后自行登录即可。
  6. “暂停库存监控”停止正常库存检查，也使本机自动重登不执行。“立即检查”会开启库存检查并请求新采集，使用前确认这是你的意图。
  7. 删除关注只移除本机监控，不会删除或修改 ERP 商品。关闭窗口只收起到托盘；完全退出要用托盘菜单。

06 · 配置库存通知机器人

  1. 在目标钉钉群创建可用的自定义机器人，取得该群的 Webhook。具体权限与操作以钉钉当前界面为准。
  2. 打开“采集设置 → 通知机器人”，添加机器人，填写便于识别的备注与 Webhook。
  3. 勾选“库存提醒”；需要货源日报或消息转发时，再勾选对应类型。每个机器人独立开关，不同接收群可以配置不同范围。
  4. 当前程序不支持机器人加签模式。使用关键词规则时，按通知范围允许“库存”“货源情况”“价格调整”。不要把密码、Webhook 或配置数据库发给其他人。
  5. 正式版会发送符合规则的新提醒。未配置、关闭或全部暂停机器人时，不能期待收到断连通知；本机断网时也可能无法发出提醒。

同一持续断连仅提醒一次，恢复后再次断开才重新判断。先给自动恢复机会，出现验证码、明确拒绝、三次重试失败或等待恢复约 5 分钟仍失败，再提醒。首次从未连接、主动暂停库存时不按断连告警处理。通知“结果未知”不会为了补发而盲目重复发送。

一键准备环境、Edge 与本地运行

当前自动重登使用 OpenCLI，普通库存采集不依赖它。 桌面程序调用本机 Node.js/OpenCLI，通过本机浏览器扩展点击登录，不需要连接 Codex 或云端 AI。ERP 请求仍发送到 ERP 网站；机器人消息仍发送到配置的钉钉机器人。不是完全离线软件，也不应把浏览器工具理解为没有任何网络访问。

一键准备入口

双击包内 一键准备运行环境.cmd。它会：

  1. 检查 Windows 10/11 64 位环境。
  2. 从 Node.js 官网下载固定版本 Node.js 24.16.0 便携包，对照官网 SHA256 清单校验。
  3. 将 Node 和 OpenCLI 1.8.6 安装到当前程序文件夹的 runtime 子目录，优先由本程序使用，不要求更改系统 Node.js，也不需要管理员全局安装。
  4. 执行 OpenCLI 环境与浏览器连接检查，打开本教程。

这是联网的一键环境准备包，不是包含所有依赖的完全离线包。第一次需要访问 nodejs.org 和 registry.npmjs.org；网络下载失败时会停止并显示原因，可恢复网络后重试。已存在完整运行环境时会复用。保留 runtime 文件夹，它是运行依赖，不是可直接删除的缓存。

扩展的安装确认、ERP 首次登录、浏览器保存密码、安装油猴脚本、机器人配置仍需人工完成。一键入口不会静默强装浏览器扩展，也不会读取、复制或填入你的密码。浏览器未连接时不能把“环境准备完成”当作“自动重登可用”。

环境入口优先使用 PowerShell 7；接收电脑没有它时，使用 Windows 自带的 Windows PowerShell 5.1，仅为运行兼容安装脚本，因此无需额外安装 PowerShell 7。不要在压缩包内直接执行。

如不想使用一键入口，可以按“安装自动重登环境”一节手动安装。程序优先找本包完整的 runtime 环境，缺失时才使用当前用户默认全局环境。

Edge 可以吗？

Microsoft Edge 支持从 Chrome Web Store 安装兼容扩展，参见 微软官方说明 ↗。但“扩展能安装”不等于“本程序整套自动重登已兼容”。

当前已实测的完整链路是 Chrome。Edge 的扩展连接、当前标签绑定、浏览器密码填充和实际自动登录尚未做整套验收；暂不作为无人值守的已支持浏览器。若试用 Edge，需要在 Edge 安装脚本管理器与 OpenCLI 扩展，并完成 doctor、绑定、退出后自动重登及新库存快照测试。不要同时让多个浏览器的扩展连接造成目标浏览器不明确。

建议先用已验证的 Chrome 部署；需要 Edge 的电脑在现场单独验证后再决定。当前安装入口不自动下载或替换浏览器。

07 · 安装自动重登环境

仅需要正常库存采集时可跳过本节，保持自动重登关闭。

  1. 从 Node.js 官网 ↗ 安装 Windows x64 的 Node.js 24 LTS，保留 npm 与 PATH 选项。当前已测版本为 24.16.0，其他补丁版本需要现场验收。
  2. 关闭旧终端，打开当前 Windows 用户的命令提示符或 PowerShell，依次执行下面的命令。使用 .cmd 可避免 PowerShell 将 npm/OpenCLI 的脚本入口拦截。
node --version
npm.cmd --version
npm.cmd install -g @jackwener/opencli@1.8.6
opencli.cmd --version
opencli.cmd doctor
  1. 从 OpenCLI 官方项目 ↗ 中的浏览器扩展入口，安装并连接 Chrome OpenCLI 扩展 ↗。ScriptCat 用来运行库存脚本；OpenCLI 扩展用来接受本机浏览器操作，两者都要启用。
  2. 按 OpenCLI 扩展和 doctor 的提示完成连接，直到浏览器连接检查通过。不要仅以“扩展已经装上”作为连接成功的判断。
  3. 重新打开库存程序，使它获得更新后的 PATH。没有包内便携 runtime 时，当前集成从 PATH（或 Node 默认安装位置）找 Node，并从 %APPDATA%\npm\node_modules\@jackwener\opencli\dist\src\main.js 找 OpenCLI。请使用当前登录 Windows 用户的默认 npm 全局安装位置；自定义 npm prefix 尚未适配。
  4. 不要为了尝试修复就随意升级 OpenCLI。当前集成验证的是 1.8.6；升级后先重做登录测试。

DWS 与 OpenCLI 是不同的工具。“钉钉监控 → 一键配置”会使用包内 DWS，不会替你安装 Node.js、OpenCLI 或 Chrome 扩展。

08 · 无人值守：开启、绑定和验收

  1. 先完成普通库存采集，确认最近成功检查时间能更新。
  2. 在库存监控页勾选“自动重登（无人值守）”。开关会保存，关闭程序后重开仍保留；取消勾选立即阻止后续自动登录操作，不停止正常库存采集。已经发出的登录请求无法撤回。
  3. 将配置好的 ERP 标签设为当前显示，等待桌面显示“ERP 已绑定”。首次绑定只能定位当前 Chrome 标签；如果是金山文档等其他网页，程序不会点击它，会提示切回 ERP。
  4. 绑定成功后可以切到其他标签。浏览器控制会检查 ERP 地址、采集脚本标记、登录页及按钮。只有填充就绪、没有验证码及明确拒绝时，才发出登录点击。
  5. 登录流程：刷新一次 → 等待至少 10 秒 → 本机点击登录 → 等待结果；最多 3 次，至少间隔 10 秒。登录后脚本恢复公司大库与搜索，本机安排一次库存检查。
  6. 正式挂机前，在有人看着时手动注销一次，随后不要点击登录。观察程序自动登录，确认仓库恢复且“最近成功检查”变成此次测试之后的时间。
  7. 失败时先处理验证码、账号状态、浏览器连接或网络。达到次数上限后，解决原因再关闭并重新打开本机自动重登开关，可开始新一轮测试。

实测记录：2026-09-13，本机程序点击 1 次恢复 ERP 登录，并在 17:28:28 写入新库存快照。 该记录证明这次交互式桌面场景成功，不代表锁屏、浏览器冷启动、断电恢复或长期连续运行均已通过验证。

09 · 挂机与系统行为边界

场景当前行为 / 要求
关闭主窗口收到托盘，程序继续工作
从托盘退出程序停止程序及钉钉监控，不能再自动重登
暂停库存监控停止普通检查，本机自动重登也不执行
仅关闭自动重登开关正常库存监控继续；登录由人工处理
ERP 分库库存标签保留，切其他页面不强制切回，可继续采集
主动关闭分库库存标签当前页面生命周期内不会强行重新打开，需要手动恢复
浏览器关闭 / 扩展断开当前程序不会自动启动浏览器或重装扩展；连接恢复后可能需重新绑定
电脑睡眠、休眠、关机或断电程序不能继续工作；需恢复 Windows 会话与程序
Windows 锁屏 / 远程桌面断开 / 无用户登录浏览器点击与持续运行尚未实测，不承诺支持
Windows 开机后自动启动本版本未提供已验收的完整开机启动链；勾选自动重登不等于开机自启
ERP 验证码、账号锁定或密码变更停止自动提交，需要人工处理

用于固定挂机电脑时，接电、保持网络、关闭自动睡眠，并保留足够磁盘空间。首次使用先有人值守验证，再观察较长时间。请勿把“自动重登”理解为无论任何故障都能自行恢复。

10 · 钉钉消息监听（按需启用）

只做库存监控，不必配置本节。

  1. 打开“钉钉监控 → 一键配置”。包内已带 DWS CLI；“一键安装到本机”准备本机运行目录，不是重新下载 ERP 或安装 OpenCLI。
  2. 点击“登录钉钉”，按出现的钉钉授权页面完成登录，再点击“刷新账号”，选择实际使用账号。
  3. 配置要监听的群和人员，点击“一键核对群和人员”。遇到多个同名结果时，根据实际对象选择，不能只凭相同名称猜测。
  4. 核对监听范围和通知机器人，完成后选择“保存并启动监控”。开始监听后只处理符合配置的新消息。
  5. 不想监听时在钉钉监控页停止；库存监控独立运行。需要消息关联、即时转发和消息来源日报时，必须有实际监听数据。

货源汇报依赖已有消息来源与采集记录。使用日报、周报或预览页面时，先核对日期、来源完整性与目标机器人；库存重登成功不代表货源数据也完整。相关页面的“预览”和“发送”含义不同，应按实际用途操作。

附录 · 库存规则与功能细节

打开程序

打开固定目录中的“后台库存监控_正式版_v1.01.exe”。正式版自动接收 ERP 采集，并使用指定群机器人发送触发的库存提醒。

库存监控可以独立使用，无需配置或启动钉钉消息监听。首次打开时，未配置的钉钉监听保持未启用；需要监听货源消息时，再进入“钉钉监控 → 一键配置”。库存提醒所用的通知机器人在“采集设置 → 通知机器人”中独立配置。

首次使用点击“＋ 添加产品”，在右侧“搜索产品”页选择“goodsid 精确搜索”或“名称模糊搜索”。goodsid 对应“基础资料 → ERP 商品 → 编号”，与 SKU 编码分开。双击结果或点击“选择并配置”，核对分类和预警数量后保存。名称支持空格分隔多个关键词；goodsid 输入完整编号。

采集完整目录后搜索覆盖全部记录，界面显示前 200 条匹配结果，可继续输入关键词缩小范围。界面展示的是最近一次成功采集的库存快照。“产品配置”页支持编辑，通过左侧导航切换功能页。

默认阈值：RTX 5070 及以上显卡（含 5070）5，其余显卡 20，主板 10，CPU 20，内存 10。特殊产品选“其他”，手动输入非负整数。单个产品手动修改后保留，不被默认值覆盖。

产品分库特例

在产品配置中，将“预警依据”从默认的“公司大库可销数”改为“指定分库库存数”，点击“刷新分库”。ERP 在线且采集脚本为 0.2.0 或更新版本时，会读取该产品在“库存查询 → 点击总库存 → 分库数查询”中显示的真实分库。

从“指定分库”选择一个库后保存。样品库也会列出，但不会自动选中或合计。比如 Colorful七彩虹 iGame RTX 5070 Advanced OC 12G 的稀缺货源有 20、样品库有 1，选稀缺货源就按 20 判断；预警数量不是总库存 21，也不是公司大库可销数 0。这里的数字是示例，实际以每次采集为准。

产品列表和通知会标明所选库及库存数。低库存、库存归零和恢复使用该数量；分库实际库存为负时称为“负库存”，可独立设置通知开关。分库特例的数量上升仅称“库存增加”，未接入对应分库入库流水时不称“确认入库”。

分库列表查询可在库存监控暂停时使用，但仍需 ERP 连接。列表超过 5 分钟需要刷新才能选择新的分库；已保存特例可直接修改预警值。查询失败、目标库不再返回或数量为空时显示“待检查”，上次数量只作参考，不改成 0。切换依据后立即重新检查，不拿两个库的数字比较变化。

升级需要同时使用新版程序和随包采集脚本；旧版脚本不支持分库时，桌面会提示更新。替换脚本后刷新 ERP 页面，再进行分库查询。原产品配置默认继续使用公司大库可销数。

连接 ERP

  1. 在平时使用 ERP 的浏览器中，将随包的 inventory-erp.user.js 安装到已有脚本猫或 Tampermonkey。它是独立的“公司大库重点产品采集”脚本，不覆盖 3cerp-js。
  2. 打开并登录 https://cqzs.3cerp.com/，进入“库房管理 → 分库库存”，仓库选择“公司大库”，点击左侧库存列表的“搜索”。保持这个 ERP 标签页及其分库库存标签打开。
  3. 点击页面右下角“库存采集：点击连接”，输入 ERP 顶栏显示的账号姓名。脚本会校验可见账号和选中的公司大库，保存的是连接范围，不是登录密码。
  4. 保持桌面程序运行。浏览器右下角变为“已更新”，桌面显示最近成功检查时间，表示第一次采集完成。

桌面程序仅在本机 127.0.0.1:18763 接收库存采集，不需要打开外网端口。浏览器扩展若询问访问本机的权限，核对目标为这个地址再处理。

如果提示等待 ERP，请检查登录状态、分库库存页是否仍打开、选中的仓库、脚本启用状态，以及桌面程序是否运行。多开浏览器标签页不会同时重复采集。

检查与通知

ERP 自动恢复与提醒：先检测断连，再给重连/自动登录最多 5 分钟恢复时间；恢复成功不提醒。浏览器明确报告验证码或 3 次登录重试耗尽，或等待超时仍未恢复时，向已启用并勾选“库存提醒”的机器人发送一次。持续断开、重启不重复；恢复后下一次断连重新判断。首次未连接、主动暂停库存监控时不提醒。浏览器关闭时无法实际重试，将等待超时后提醒；本机断网时机器人也可能无法发送。

自动重登请使用随包 0.4.0 脚本，由本机“自动重登（无人值守）”开关统一控制。浏览器保存密码，本机程序通过 OpenCLI 操作登录按钮；旧版油猴重复点击方案不再作为可用方案。详见下文完整教程。

移除重点产品：在左侧列表选中产品，点击“删除关注”。待发送和待重试提醒会取消；已经进入发送的通知可能仍会送达。ERP 商品目录不受影响，可在右侧重新搜索添加。

  • 默认每 2 小时检查一次，可在采集设置修改周期；点击“立即检查”可提前检查。浏览器心跳只判断连接状态，不会每次都查询库存。
  • 公司大库可销数小于或等于阈值：低库存；小于 0：超售。同一持续状态不重复发送，恢复后通知一次。
  • 入库提醒来自 ERP 分库库存账中的“入库单”，不把调拨或释放订单占用当作入库。首次连接对历史流水建立基线，不补发历史入库提醒。
  • 入库流水每轮回查最近 30 天；长时间离线时从上次检查前一天补查。晚补且倒填到这段范围之前的单据无法自动发现。同一单据原记录的数量修改不会作为新入库重复提醒。
  • 三类通知只使用已配置的群自定义机器人，不使用个人账号发送。进入“采集设置 → 通知机器人”添加多个机器人，填写备注和 Webhook，分别勾选库存提醒、货源日报、货源消息即时转发。
  • 备注不必与实际群名一致，Webhook 决定目标群。关键词按所选类型添加“库存”“货源情况”“价格调整”，当前不支持加签模式。地址通过 Windows 用户绑定加密保存，不在界面回显。
  • 每个机器人可单独暂停或恢复。暂停期间其他机器人继续发送；恢复只接收新消息，不补发暂停期间积压。已经开始的请求可能仍送达。未配置或全部暂停时，该次通知记为跳过。
  • 每个机器人有独立投递结果。已成功及结果未知的接收方不自动重发；明确可重试的失败才按退避重试。旧库存/日报和消息机器人按原通知范围迁移。
  • 正式版开启机器人自动发送；首次升级会取消测试积压，立即请求新采集。保留的“启动本地测试.cmd”仅用于不发送消息的调试，请勿与正式版同时运行。
  • 结果不明的通知会保留“待核实”，不自动重复发送。明确失败才按退避重试。
  • 产品关键词应填写完整型号和规格，例如品牌、系列、容量组合，逗号分隔。宽泛的“显卡”“5070”不适合作为型号别名。消息匹配歧义时不自动关联。

数据与运行边界

关闭窗口会收起到托盘，监控继续；从托盘选择“退出程序（同时停止钉钉监控）”才完全退出。关闭 ERP、退出登录、电脑休眠时库存采集暂停；恢复连接后补一次检查。每 2 小时检查不能保证捕捉期间短暂发生又恢复的低库存。

本机升级沿用程序目录 .local_inventory_ui_test/inventory.sqlite3 保存配置和历史，文件夹名称为兼容旧版保留。统一机器人配置位于本机用户目录 %LOCALAPPDATA%/DingTalkSourceMonitor/data/notification_robots.sqlite3，凭据加密保存，勿随分发包转发。升级时同时保留上述数据。不要用另一台机器的数据库覆盖自己的记录。数据文件损坏时程序报错，不自动清空。

更新时关闭旧版后再打开新版，保留数据目录。给其他部门分发时仅分发 EXE、采集脚本和说明，不分发本机数据目录；接收部门自行配置产品及群机器人。产品经理消息关联仍需要已有消息监听服务提供来源记录。
